# 시나리오별 알고리즘 비교 웹 데모 구현 계획

**구현 상태:** 로컬 데모를 추가했다. 실행 방법은 [README](../README.md#local-demonstration)를 확인한다.

## 1. 만들려는 화면

발표 중에 **시나리오를 고르고 → 같은 작업의 알고리즘별 결과를 비교하고 → 창고에서 경로가 어떻게 달라지는지 재생**하는 로컬 웹 데모를 만든다.

처음에는 저장된 평가 결과를 보여준다. 발표자가 원하면 같은 입력과 설정으로 다시 계산한다. 기존 실험 결과를 변경하거나 전체 실험을 다시 실행할 필요는 없다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 창고 피킹 경로 비교   [저장 결과 보기 / 지금 다시 계산]        │
├──────────────────────────────────────────────────────────────┤
│ 시나리오 A–H · 위치 수 · 배치 · 출발점 · seed · 작업 ID       │
│ [발표 예제 선택]     조건 설명과 선택된 작업의 특징            │
├─────────────────────────────┬────────────────────────────────┤
│ 알고리즘 A의 창고 경로       │ 알고리즘 B의 창고 경로          │
│ 출발 S · 물건 · 도착 C       │ 동일한 작업, 동일한 지도        │
│ [재생] [일시정지] [처음으로] · 진행 슬라이더 · 속도            │
├─────────────────────────────┴────────────────────────────────┤
│ 9개 후보 비교표: 거리 · 시간 · 상태 · 반환 방법 · 최적성       │
│ 저장된 선택 규칙: 무엇을 골랐고, 어떤 조건으로 골랐는지       │
├──────────────────────────────────────────────────────────────┤
│ 선택 조건의 전체 결과: 거리 · 시간 · 완료율 · 표본 수         │
│ 개별 작업의 결과와 전체 경향을 구분하는 설명                  │
└──────────────────────────────────────────────────────────────┘
```

UI는 한국어로 작성한다. 처음 보는 사람에게는 `completed` 대신 “완료”, `timeout` 대신 “시간 초과”를 보여주고, 필요할 때 원래 상태값도 확인할 수 있도록 한다.

## 2. 발표 중 사용할 흐름

1. **작은 작업:** 같은 위치들을 NN과 DP가 어떤 순서로 방문하는지 비교한다. 완료된 DP에만 최적해 표시를 붙인다.
2. **경로 개선:** NN과 NN+2-opt를 나란히 놓고, 같은 작업에서 얼마나 거리가 줄었는지 본다. 두 경로를 각각 재생하고 필요하면 겹쳐 본다.
3. **큰 작업:** 위치 수를 15, 20, 50으로 바꾸어 DP의 시간 초과 또는 설정된 크기 제한을 확인한다. 요청 모드에서는 그때 실제 반환된 NN 대체 경로도 표시한다.
4. **출발점 변경:** 물건 집합은 유지하고 시작 위치만 바꾼 H 작업을 비교한다.
5. **선택 규칙:** “항상 NN+2-opt”와 저장된 개수 기반 정책을 비교한다. 현재 규칙이 `n <= 13.5`에서 DP를 고르는 이유를 조건식으로 보여준다.

예제 버튼에는 실제 기록에서 확인한 작업을 연결한다. 발표용 예제는 설명을 위해 고른 사례라고 표시하고, 전체 성능의 대표값처럼 설명하지 않는다. 개선 폭이 없는 사례도 사용자가 직접 선택할 수 있다.

## 3. 시나리오 A–H를 화면에 연결하는 방법

A–H는 서로 겹치는 실험 관점이다. 시나리오를 고르면 해당 질문에 맞는 기본 필터와 비교 후보를 설정하며, 사용자는 세부 조건을 바꿀 수 있다.

| 시나리오 | 화면에서 확인할 내용 | 기본 비교 |
|---|---|---|
| A: 작은 작업의 정확성 | 같은 작업에서 정확 방법의 거리가 일치하는가? | Exhaustive / DP |
| B: DP 계산 규모 | 위치 수가 늘어날 때 시간과 상태가 어떻게 바뀌는가? | DP / NN+2-opt |
| C: 큰 작업 | 빠른 방법들 사이에서 거리와 계산 비용이 어떻게 다른가? | NN / NN+2-opt, 전체 후보 표 |
| D: 군집 배치 | 물건이 모여 있을 때 추가 개선이 도움이 되는가? | NN / NN+2-opt |
| E: 분산도 | 실제 dispersion 값에 따라 개선 폭이 어떻게 다른가? | NN / NN+2-opt |
| F: 컨베이어와의 관계 | 동일 seed·n·출발점의 좌우 반사 쌍에서 무엇이 달라지는가? | 같은 방법의 far / near 작업 |
| G: 방향성·패턴 | 배치와 실현된 거리 특징에 따라 어떤 차이가 있는가? | NN / CA-minus, 패턴별 집계 |
| H: 출발점 | 동일 물건 집합에서 출발점만 바꾸면 경로가 어떻게 달라지는가? | 같은 방법, 다른 시작점 |

F와 H에서는 서로 짝인 작업을 자동으로 찾고, 일치하는 물건 수·seed·조건을 화면에 표시한다. 짝이 없으면 비교할 수 없다고 안내한다.

E는 실제 dispersion 숫자를 우선 보여준다. 기존 결과의 평가용 중앙값 구분을 사용한다면 “분석을 위한 기술적 구분”이라고 명시한다. F는 출발점 거리도 바뀌므로 컨베이어 거리만의 인과 효과라고 설명하지 않는다.

## 4. 결과표에 표시할 값

| 값 | 표시 원칙 |
|---|---|
| 경로 거리 | S부터 물건들을 거쳐 C까지의 통로 거리, 단위 m |
| 계산 시간 | 단위 ms. 후보 탐색 시간인지 전체 요청 시간인지 표 제목에 표시 |
| 완료 상태 | 완료, 시간 초과, 크기·메모리 제한, 오류 등을 유지 |
| 종료 사유 | 2-opt의 지역 최적점 도달과 평가 횟수 제한을 구분 |
| 요청한 방법 / 반환한 방법 | DP 실패 뒤 NN 경로가 나왔다면 두 방법을 모두 표시 |
| 최적성 | 완료된 정확 방법이 실제로 증명한 경우에만 “최적해 확인” 표시 |
| NN 대비 거리 차이 | 동일 작업의 유효한 NN 결과가 있을 때 계산 |
| 최적해 대비 차이 | 해당 작업에 완료된 정확해가 있을 때만 계산 |
| 실행 조건 | 계수, 시간 예산, 크기 제한, 측정 출처를 상세 영역에서 확인 |

선택 조건의 전체 집계에는 시도 수, 완료 수, 상태별 비율을 먼저 보여준다. 거리와 시간의 중앙값은 어떤 완료 표본에서 계산했는지 함께 표시한다. 서로 다른 입력에서 나온 최저 거리를 공정한 알고리즘 순위처럼 표시하지 않는다.

기본 화면은 평가 데이터만 사용하고, 개발 데이터로 바꾸면 그 사실을 눈에 띄게 표시한다. 선택 규칙은 저장된 규칙을 읽어 보여주며, UI에서 평가 결과를 이용해 규칙을 다시 학습하지 않는다.

## 5. 창고 경로를 어떻게 그릴까?

기존 `build_warehouse()`의 좌표와 간선으로 SVG 지도를 그린다. 시작점 S, 도착점 C, 필요한 선반 위치를 구분하고, 물건 위치의 방문 순서에 번호를 붙인다.

요청 기록에 있는 `path`는 그대로 사용한다. 후보 자체 기록에는 방문 순서만 있으므로, 선택한 작업의 거리표를 준비하고 `DistanceTable.reconstruct()`로 실제 통로 경로를 복원한다. 이 과정은 시각화용 처리이며 과거 실험의 계산 시간에 더하지 않는다. 복원 후 기존 `validate_path()`로 기록된 거리와 일치하는지 확인한다. 실패하면 경로 대신 불일치 안내를 표시한다.

재생은 실제 통로 선분을 따라 이동하는 점으로 표현한다. 이동 거리에 비례한 진행률을 사용하고, 과거의 알고리즘 계산 과정을 재현하는 애니메이션이라고 설명하지 않는다. 이동 속도는 시각화 속도이며 실제 작업자 속도나 실제 작업 시간 추정값이 아니다.

처음에는 두 개의 나란한 지도와 재생·정지·초기화·진행 슬라이더만 구현한다. 마우스 외에도 키보드로 버튼과 슬라이더를 사용할 수 있게 하고, 색상 외에 선 모양과 라벨로도 방법을 구분한다.

## 6. 저장 결과와 실시간 계산

**저장 결과 보기**는 `results/full`의 기존 실험 기록을 읽는다. 실험 당시의 시간과 실행 조건을 유지하므로 발표 중 다시 계산한 결과가 달라져도 원래 근거가 바뀌지 않는다.

**지금 다시 계산**은 사용자가 선택한 동일 작업에 대해 선택한 두 후보만 순차 실행한다. 한 번에 전체 4,050개 작업을 실행하지 않는다. 입력과 알고리즘 설정을 검증하고, 기존 시간·크기·메모리 추정 제한을 유지한다.

실시간 결과에는 “이번 데모에서 재측정”, 실행 시각과 조건을 표시한다. 저장 결과를 덮어쓰지 않고 세션 안에서 따로 보여준다. 계산 중에는 진행 상태를 표시하고 중복 실행을 막는다. 실패해도 이미 보고 있던 저장 결과는 유지한다.

시간 측정 의미를 보존하기 위해 알고리즘을 동시에 실행하지 않는다. 기본값은 본실험의 0.2초와 CA 계수 0.5로 맞추고, 설정을 변경하면 본실험 조건과 달라졌다는 사실을 표시한다.

## 7. 구현 방식과 파일 범위

추천하는 첫 구현은 **Python 표준 라이브러리 로컬 서버 + HTML/CSS/JavaScript + SVG**다. 기존 프로젝트는 Python이고, 현재 환경에는 Streamlit이 설치되어 있지 않다. 계산 함수를 그대로 호출하면서 별도 설치 없이 데모를 열 수 있는 작은 구성이 적절하다.

```text
python3 -m demo
    ↓
localhost의 웹페이지
    ├─ 저장 결과 조회·필터·집계
    ├─ 작업별 경로 표시·재생
    └─ 선택한 두 후보의 재계산 요청
```

서버는 기본적으로 `127.0.0.1`에만 연결한다. 시연 대상은 이 컴퓨터의 브라우저이며, 외부에 공유하는 배포는 별도 범위다. 사용자 입력은 고정된 작업 ID와 허용된 알고리즘·설정으로 검증한다. 임의 파일 경로나 명령을 요청받아 실행하지 않는다.

| 추가·수정 위치 | 책임 |
|---|---|
| `demo/__main__.py` | 로컬 서버, 결과 데이터 인덱스, 조회·재계산 API |
| `demo/index.html` | 한국어 화면, 접근 가능한 입력과 비교표 |
| `demo/app.js` | 필터, API 호출, SVG 경로, 재생 제어 |
| `demo/style.css` | 발표용 화면, 두 지도 배치, 좁은 화면 대응 |
| `tests/test_demo.py` | 결과 정규화, 짝 찾기, 경로 검증, 입력 검증 |
| `README.md` | 실행법과 데이터가 없을 때 준비 방법 |

기존 `picking/`, `experiments/`, 실험 원시 기록을 재사용한다. 새 데모 코드는 별도 `demo/`에 둬서 기존 규칙의 코드 지문과 연구 결과를 보존한다.

원시 기록은 크므로 매 클릭마다 다시 읽거나 브라우저에 통째로 보내지 않는다. 서버 시작 때 필요한 필드만 읽어 작업 ID·측정 종류·알고리즘별로 인덱싱한다. 브라우저에는 필터 목록, 집계, 선택한 작업의 결과만 보낸다. 시각화용 거리표는 선택한 작업에 대해서만 계산하고 캐시한다. 데이터가 없거나 손상된 경우에는 원인과 준비 방법을 화면에 표시한다.

## 8. 구현 순서와 완료 기준

| 순서 | 구현할 것 | 완료 확인 |
|---|---|---|
| 1 | 저장 결과 로딩과 한 작업의 비교표 | 기존 JSONL의 거리·시간·상태와 UI 값이 일치한다. |
| 2 | 두 지도와 실제 경로 재생 | S와 C가 맞고, 선반을 가로지르지 않으며, 복원 거리가 기록과 일치한다. |
| 3 | A–H 시나리오·필터·짝 비교 | F와 H에서 올바른 관련 작업을 찾고, 빈 결과도 정상 안내한다. |
| 4 | 조건별 집계와 규칙 설명 | 실패가 누락되지 않고, 동일 입력의 비교와 집계 표본 수를 확인할 수 있다. |
| 5 | 선택 후보 재계산 | 기존 기록을 유지하며, 새 실행 시간과 fallback을 구분한다. |
| 6 | 발표 흐름 검증과 실행 안내 | 새 터미널에서 한 명령으로 열고 예제 5단계를 끝까지 시연할 수 있다. |

자동 검증에서는 기록→화면용 데이터 변환, 잘못된 작업 ID와 설정 거부, F/H 짝 연결, 경로 거리 일치, 시간 초과 뒤 실제 반환 방법을 확인한다. 기존 테스트도 실행한다.

브라우저에서는 필터 변경, 알고리즘 전환, 재생·정지·초기화, 키보드 조작, 작은 화면, 데이터 없음, 재계산 실패를 직접 점검한다. 서버와 화면을 실제로 연결한 상태에서 발표 예제를 끝까지 실행한다.

## 9. 이번 구현 범위

첫 버전의 목표는 **같은 작업에서 알고리즘이 어떻게 다른 경로와 결과를 내는지 눈으로 비교하는 발표 도구**다. 로그인, 클라우드 배포, 창고 편집기, 물건 직접 배치, 다중 작업자, 3D 지도는 포함하지 않는다.

가장 먼저 저장 결과 조회와 두 경로 비교를 완성한다. 이 기능만으로 이미 끝난 실험을 시연할 수 있고, 이후 재계산 기능을 붙여 조건 변화도 설명할 수 있다. 이 문서는 구현 당시의 계획과 완료 기준을 기록한다.
